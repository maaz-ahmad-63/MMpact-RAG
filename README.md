# Universal RAG Service

Universal RAG is a completely standalone document ingestion and semantic retrieval service powered by FastAPI, PostgreSQL, and pgvector. It provides a simple, secure, and robust backend for external AI agents or services to upload files, clean and chunk them, generate vector embeddings, and search for context on-demand.

---

## Architecture

```
Client / External AI Agent
        |
        | HTTP API (JSON + Multipart)
        v
Universal RAG Service (FastAPI)
        |
        +-- Ingestion (PDF, DOCX, TXT)
        +-- Text Cleaning & Normalization
        +-- Semantic Chunking
        +-- Embeddings Generation (HTTP API or In-Process Local Transformer)
        +-- Vector Search & Cosine Similarity
        |
        v
PostgreSQL + pgvector
```

---

## Prerequisites

1. **Python**: 3.11 or 3.12
2. **PostgreSQL**: Version 12+ with the `pgvector` extension installed.
3. **Embedding Backend**: A running embedding server (e.g., TEI, Ollama, Infinity, vLLM) OR `sentence-transformers` installed locally for in-process embeddings.

## Installation & Setup

### 1. Clone & Set Up Virtual Environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. PostgreSQL + pgvector Setup

Ensure you have a PostgreSQL database running and the `pgvector` extension installed. You can enable the extension by running the following SQL command on your database:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 3. Environment Setup

Copy `.env.example` to `.env` and fill in your details:

```bash
cp .env.example .env
```

Key environment configurations:
- `RAG_DATABASE_URL`: Connection string for PostgreSQL (e.g., `postgresql://postgres:postgres@localhost:5432/rag_db`).
- `RAG_API_TOKEN`: Shared token for endpoint authorization. If left blank, RAG endpoints run unauthenticated (only suitable for private networks).
- `EMBEDDING_MODEL`: The model identifier (defaults to `BAAI/bge-m3`).
- `EMBEDDING_BACKEND`: Set to `http` if using an external embedding provider, or `local` for in-process CPU/GPU embedding (requires `pip install sentence-transformers`).

### 4. Database Migrations

Run the script to create the necessary tables (`rag_documents` and `rag_chunks`):

```bash
python -m app.rag.migrate
```

---

## Running Locally

To run the FastAPI server locally:

```bash
python -m app.main
```

The application runs by default on `http://localhost:8000`. You can inspect the Swagger UI at `http://localhost:8000/docs`.

---

## API Authentication

- The root endpoint `GET /` requires **no authentication**.
- All RAG endpoints (`/api/rag/*`) enforce bearer token authentication if `RAG_API_TOKEN` is configured in the environment.
- Accessing protected endpoints requires setting the header:
  `Authorization: Bearer <your-rag-api-token>`

## API References & Examples

### 1. Root Health Check
- **Endpoint**: `GET /`
- **Auth Required**: No
- **Response**:
  ```json
  {
    "status": "healthy",
    "service": "Universal RAG Service"
  }
  ```

### 2. RAG Diagnostic Health
- **Endpoint**: `GET /api/rag/health`
- **Description**: Verifies database connection, column dimensions, and embedding model availability.
- **Example Curl**:
  ```bash
  curl -X GET http://localhost:8000/api/rag/health \
    -H "Authorization: Bearer change-me-rag-token"
  ```

### 3. Upload & Ingest Document
- **Endpoint**: `POST /api/rag/upload`
- **Request Format**: `multipart/form-data`
  - `file`: PDF, DOCX, or TXT file (Required).
  - `document_id`: Optional custom ID. Autogenerated if omitted.
  - `user_id`: Optional user scope tag.
  - `agent_id`: Optional agent scope tag.
  - `conversation_id`: Optional conversation scope tag.
  - `metadata`: Optional JSON string (e.g. `{"tenant":"acme"}`).
- **Example Curl**:
  ```bash
  curl -X POST http://localhost:8000/api/rag/upload \
    -H "Authorization: Bearer change-me-rag-token" \
    -F "file=@policy.pdf" \
    -F "metadata={\"department\":\"HR\"}"
  ```

### 4. Vector Similarity Search
- **Endpoint**: `POST /api/rag/search`
- **Description**: Accept a raw text query, generate query embedding, and perform similarity search against stored chunks.
- **Request Body**:
  ```json
  {
    "query": "What is the refund policy?",
    "top_k": 5,
    "threshold": 0.70
  }
  ```
- **Example Curl**:
  ```bash
  curl -X POST http://localhost:8000/api/rag/search \
    -H "Authorization: Bearer change-me-rag-token" \
    -H "Content-Type: application/json" \
    -d '{"query": "What is the refund policy?", "top_k": 3}'
  ```

### 5. Build Context (Prompt-Ready Context)
- **Endpoint**: `POST /api/rag/context`
- **Description**: Same retrieval logic as `/search`, but compiles text excerpts directly into a single, prompt-ready context block for your AI models.
- **Request Body**:
  ```json
  {
    "query": "What is the refund policy?",
    "max_chars": 6000,
    "top_k": 5
  }
  ```
- **Example Response**:
  ```json
  {
    "query": "What is the refund policy?",
    "found": true,
    "context": "[1] policy.pdf, page 4\nRefunds are processed within 30 days of standard purchase...",
    "sources": [
      {
        "document_id": "doc_abc123",
        "source": "policy.pdf",
        "page": 4,
        "chunk_index": 1,
        "similarity": 0.912421
      }
    ],
    "chunks_used": 1,
    "took_ms": 15
  }
  ```

### 6. List Documents
- **Endpoint**: `GET /api/rag/documents`
- **Description**: List ingested documents, sorted by ingest date (newest first). Paginated.
- **Example Curl**:
  ```bash
  curl -X GET "http://localhost:8000/api/rag/documents?limit=10&offset=0" \
    -H "Authorization: Bearer change-me-rag-token"
  ```

### 7. Get Document Details
- **Endpoint**: `GET /api/rag/documents/{document_id}`
- **Example Curl**:
  ```bash
  curl -X GET http://localhost:8000/api/rag/documents/doc_abc123 \
    -H "Authorization: Bearer change-me-rag-token"
  ```

### 8. Delete Document
- **Endpoint**: `DELETE /api/rag/documents/{document_id}`
- **Description**: Safely deletes the document and all associated chunks and vector embeddings in a single atomic transaction.
- **Example Curl**:
  ```bash
  curl -X DELETE http://localhost:8000/api/rag/documents/doc_abc123 \
    -H "Authorization: Bearer change-me-rag-token"
  ```

### 9. Retrieve Search Logs (MongoDB)
- **Endpoint**: `GET /api/logs/searches`
- **Description**: Retrieve recent search query logs and execution analytics from MongoDB.
- **Query Parameters**:
  - `limit`: Number of records to return (default: 50, maximum: 200).
  - `document_id`: Filter logs by retrieved document ID.
  - `found`: Filter logs by whether any chunks matched similarity thresholds.
- **Example Curl**:
  ```bash
  curl -X GET "http://localhost:8000/api/logs/searches?limit=10&found=true" \
    -H "Authorization: Bearer change-me-rag-token"
  ```

## Database Schema Architecture

The migration defines two tables in your configured schema (default `public`):

1. **`rag_documents`**
   - Keeps track of document-level metadata.
   - Columns: `id` (primary key), `filename`, `file_type`, `file_path`, `user_id`, `agent_id`, `conversation_id`, `metadata` (JSONB), `created_at`.

2. **`rag_chunks`**
   - Stores segmented chunks, the corresponding plain text, and vector embeddings.
   - Columns: `id` (primary key), `document_id` (foreign key pointing to `rag_documents`), `chunk_index`, `content`, `embedding` (type `vector`), `metadata` (JSONB).
   - An index is built on the `embedding` column matching the configured distance metric (e.g. HNSW or IVFFlat with Cosine, L2, or Inner Product).

## Integrating with AI Agents

Your external conversational AI Agent can easily consume this service. During a chat interaction:

1. **Check Eligibility**: Check the user prompt.
2. **Context Retrieval**: Call `POST /api/rag/context` passing the user's message as the query.
3. **Format Prompt**: Inject the returned `context` string into your LLM prompt template:
   ```
   You are a helpful AI assistant. Use the following context to answer the user request.
   
   Context:
   {{ retrieved_context }}
   
   User Request:
   {{ user_query }}
   ```
4. Respond: Pass the compiled prompt to your chat model provider (e.g. OpenAI, Anthropic, Gemini).

## MongoDB Logging & Analytics
MongoDB is integrated as an optional, non-blocking telemetry layer for search tracking and analytics. PostgreSQL with pgvector remains the primary store for document metadata, chunk text, and embeddings.

To configure MongoDB logging, add the following variables to your `.env` file:
```env
MONGODB_URL=mongodb://localhost:27017/
MONGODB_DATABASE=universal_rag
MONGODB_COLLECTION=rag_logs
```

If `MONGODB_URL` is left blank, MongoDB connections are skipped and logging is gracefully disabled without affecting any RAG search operations. Indexes on `timestamp`, `document_ids`, and `found` are automatically built on startup.
